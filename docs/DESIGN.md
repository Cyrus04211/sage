# SAGE 技术设计文档

## 1. 项目概述

SAGE 是一个 Gurobi 求解器参数自动调优系统。给定一组同类的 MIP 问题实例（本项目中为
16 个 IEEE-118 节点机组组合实例），系统自动选出一组求解器参数配置，使该配置在整个
实例集上的平均求解表现（PDI，越小越好）优于 Gurobi 默认配置。最终交付物是一个
`.prm` 参数文件，可直接用于生产环境。

系统由两部分协作完成调参：

- **LLM 代理**：负责需要领域知识的决策——确定调哪些参数、给出初始候选配置、总结调参经验；
- **SMAC3 优化器**：负责具体的参数搜索——在实例集上评估候选配置、用贝叶斯优化模型
  选择下一个待评估配置。

LLM 的决策有两个外部知识来源：

- **Gurobi 13.0 参数手册**：预先解析为结构化检索库，LLM 通过检索接口查询参数说明、
  类型、默认值和取值范围；
- **历史调参记录库**：每次调参任务结束后，任务记录（选了哪些参数、搜索轨迹、最优配置、
  测试集表现）持久保存；新的调参任务开始时，按实例特征相似度检索历史记录，复用其中的
  参数子空间和优质配置。

## 3. 系统组成

```
sage/
├── observe/     实例特征提取与实例集画像
├── rag/         Gurobi 参数手册检索库（构建 + 查询）
├── memory/      历史调参记录库（写入 + 检索 + 定期总结）
├── agent/       LLM 代理（LangGraph 实现，含工具定义与提示词）
├── smac_loop/   SMAC3 搜索循环、配置空间构建、评估器、参数重要性分析
└── llm/         LLM API（OpenAI 兼容协议）调用封装
```

### 3.1 实例特征提取（observe）

对每个实例提取两类特征，结果缓存到磁盘，整个实例集只做一次。

- **静态特征**（gurobipy 读取模型属性与约束矩阵统计）：变量/约束/非零元数量、
  二进制与整数变量占比、约束类型分布（≤/≥/=）、矩阵密度与系数量级、UC 问题特有信息
  （从变量命名推断的机组数、时段数等）；
- **动态特征**（用默认参数做 60–120 秒试解）：根节点 LP 松弛目标值与耗时、初始对偶间隙、
  分支定界节点数、各类割平面生效数量、预处理削减比例、首个可行解时间。

实例集画像 = 各特征在实例集上的统计汇总（均值/极差）+ 一段自动生成的文字描述，
文字描述供 LLM 阅读；实例集之间的相似度比较使用**数值特征向量**（见 3.3），
不依赖文字描述。

单实例静态特征向量同时提供给 SMAC，作为其实例特征输入（SMAC 的代理模型据此学习
"参数配置 × 实例特征"对求解表现的影响）。

### 3.2 手册检索库（rag）

**构建**（离线，一次）：抓取 Gurobi 13.0 参数参考页
（`https://docs.gurobi.com/projects/optimizer/en/13.0/reference/parameters.html`），
按参数切分为约 200 条记录，每条包含参数名、类型、默认值、取值范围、说明文字、
是否仅对 MIP 生效。对说明文字建立 BM25 索引（`bm25s` 库），与结构化记录一起
持久化到 `rag_index/`。

**查询**：语料仅约 200 条，无需向量检索，两种方式：

1. **关键词检索**：按参数名或功能关键词做 BM25 检索，取前 5 条——用于核对取值范围；
2. **清单选择**：将全部参数的"名称 + 一句话功能"压缩清单（约数千 token）直接放入
   LLM 提示词，由 LLM 根据问题症状（如"根节点松弛求解慢"）圈定候选参数，再按名称
   取回完整手册条目——用于生成候选参数列表。

**约束**：LLM 给出的参数取值范围必须是手册记录范围的子集，系统在构建配置空间时
强制校验。

### 3.3 历史调参记录库（memory）

每次调参任务结束后写入一条记录（JSON 格式，逐行追加到 `campaigns.jsonl`）。
记录内容：

```json
{"id": "uc118_campaign_003",
 "family": {"name": "uc-ieee118", "n_instances": 12,
            "feature_vector": {"nvars_mean": 152300, "binary_ratio_mean": 0.61, "...": "..."},
            "description": "实例集画像文字（仅供 LLM 阅读）",
            "split": {"train": [...], "test": [...]}},
 "selected_params": [{"name": "Cuts", "range": [-1, 2], "reason": "..."}],
 "warmstart_configs": [{"MIPFocus": 1, "Cuts": 2, "..." : "..."}],
 "best_config": {"MIPFocus": 1, "Cuts": 2, "..." : "..."},
 "performance": {"train_avg_pdi": 158.2, "test_avg_pdi": 167.5,
                 "default_test_avg_pdi": 245.1,
                 "n_trials": 240, "walltime_h": 18.5},
 "param_importance": {"Cuts": 0.41, "MIPFocus": 0.33},
 "lessons": "文字总结：哪些改动有效、哪些无效",
 "timestamp": "..."}
```

- **写入条件**：仅当测试集表现优于默认配置时入库，避免无效经验污染后续任务；
- **检索**：新任务开始时，将当前实例集的数值特征向量与库中各记录的 `feature_vector`
  做 z-score 标准化后的欧氏距离比较，取最近的 5 条成功记录交给 LLM 参考。
  纯 numpy 实现，无需向量数据库或嵌入模型；
- **定期总结**：同一实例族累计 4 条记录后，由 LLM 归纳一条该族的通用调参经验，
  作为高优先级记录入库。

### 3.4 LLM 代理（agent）

用 LangGraph 实现，LLM 可调用四个工具：

| 工具 | 功能 |
|---|---|
| `search_manual(query)` | 查询 Gurobi 参数手册检索库（见 3.2） |
| `recall_campaigns()` | 按特征向量相似度检索历史调参记录（见 3.3） |
| `get_family_report()` | 返回当前实例集的特征报告（见 3.1） |
| `record_campaign(record)` | 写入调参记录（调参结束后调用） |

代理的三项决策任务：

1. **选择参数子空间**：根据实例集画像、历史记录和手册查询结果，从约 200 个 Gurobi
   参数中选出 k 个（默认 8 个）参与调参，并给出每个参数的搜索范围（不得超出手册范围）
   和选择理由；
2. **生成初始配置**：给出 N₀ 个（默认 8 个）候选参数配置，来源包括历史记录中的最优配置、
   手册默认值、以及基于实例特征的调整，作为 SMAC 搜索的起点；
3. **中期调整**（可选）：搜索进行到一半时，根据已评估配置的重要性分析结果
   （见 3.6），决定是否替换 1–2 个贡献最小的参数。

所有 LLM 输出按预定义 JSON 模式校验，不合法则要求重新生成。

### 3.5 LLM 调用

LLM 通过 API 调用，采用 OpenAI 兼容协议（`openai` Python SDK，自动读取
`OPENAI_BASE_URL` / `OPENAI_API_KEY` 环境变量；模型名由 `LLM_MODEL` 指定）。
配置存放于项目根目录 `.env`，不进入代码库。服务器访问外网需经本机代理
（`127.0.0.1:7890`，由 `.env` 中的 `HTTP_PROXY` / `HTTPS_PROXY` 指定，SDK 自动生效）。
LangGraph 代理经 `ChatOpenAI` 接入，更换服务商时只需修改 `.env`。

系统不部署任何本地模型：手册检索用 BM25，记忆检索用数值特征距离，均不依赖
嵌入模型（见 3.2、3.3）。

### 3.6 SMAC 搜索循环（smac_loop）

使用 SMAC3 的 `AlgorithmConfigurationFacade`，配置要点：

- 搜索空间：由 3.4 选出的 k 个参数构成（ConfigSpace），默认值锚点为 Gurobi 默认配置；
- 实例设置：`Scenario(instances=训练实例列表, instance_features=静态特征)`，
  SMAC 的 intensifier 机制自动在实例间分配评估——表现差的候选配置在少量实例上评估后
  即被淘汰，预算集中在有希望的配置上；
- 初始设计：LLM 给出的 N₀ 个初始配置 + Gurobi 默认配置（`additional_configs`）；
- 并行：`n_workers=8`，每个 worker 内 Gurobi 单线程运行；
- 预算：总墙钟时间（默认 24 小时）+ 单次评估上限 300 秒，超时按最差表现计入。

**评估器**：输入 (参数配置, 实例)，输出该配置下求解该实例的 PDI。为提高效率，
每个 worker 进程内已加载的模型驻留内存，评估之间只重置参数和求解状态
（`setParam` → `optimize` → `reset`），不重新读取 550MB 的 `.lp` 文件。
PDI 通过 Gurobi callback 记录求解过程中 primal/dual 界的时间序列计算
（左黎曼和，与 GRIMIP 论文附录 E 一致）。

**中期参数重要性分析**：搜索过半时，从 SMAC 的 runhistory 导出全部已评估
(配置, 实例特征, PDI) 数据，用 fANOVA（`optuna-fast-fanova`）计算各参数的重要性，
交给 LLM 做中期调整决策（见 3.4 第 3 项）。调整后保留已有评估数据，继续搜索。

## 4. 工作流程

一次完整调参任务按以下步骤执行：

1. **特征提取**：对训练实例集提取静态与动态特征，生成实例集画像（首次运行时执行，
   结果缓存）；
2. **检索历史**：按数值特征向量相似度检索历史调参记录（最多 5 条）；
3. **选择空间**：LLM 结合画像、历史记录、手册检索，选出 k 个参数及各自搜索范围，
   生成 N₀ 个初始配置；
4. **构建搜索**：按选定参数构建 ConfigSpace（校验参数名与范围合法性），
   初始化 SMAC（注入初始配置与默认配置）；
5. **搜索**：SMAC 在训练实例集上迭代评估候选配置，直到预算耗尽；
   搜索过半时执行一次中期重要性分析与参数调整（可选）；
6. **验证**：最优配置在测试实例集上复跑 5 次，报告平均 PDI；
7. **记录**：任务结果写入历史调参记录库；满足条件时触发定期总结。

## 5. 实验方案

**数据**：16 个 IEEE-118 实例按 12 训练 / 4 测试划分，3 种随机种子重复。
2746 节点实例（6 个，每个约 4GB）不参与调参，仅用于最终的跨实例族迁移验证。

**对比方法**（均为"一个配置用于整个实例集"，调参墙钟预算对齐）：

- Gurobi 默认配置；
- `grbtune`（Gurobi 官方调参工具，多模型模式）；
- SMAC3 直接调参（相同搜索空间，随机初始设计，无 LLM 参与）；
- SAGE 完整流程。

另以 per-instance 调参（每个实例单独调一组参数）的最优表现作为性能上界参考，
报告 SAGE 与该上界的差距。

**消融实验**：分别移除手册检索、历史记录、初始配置生成、中期调整，验证各模块贡献。

**顺序实验**：模拟实例分批到达（4 → 8 → 12 → 16 个），每批到达后基于历史记录
重新调参，考察调参效率随记录积累的变化。

**协议**：单次评估 300 秒上限、Gurobi 单线程、最终配置测试集复跑 5 次、
固定 Gurobi 13.0.1。

```bash
# 服务器上执行
cd /home/lgl/projects/sage
python3.12 -m venv .venv && source .venv/bin/activate   # 若无 venv 模块则用 virtualenv
pip install gurobipy==13.0.1 smac "scikit-learn>=1.6.1,<1.8" ConfigSpace \
    openai langchain-openai python-dotenv langgraph langchain \
    bm25s optuna-fast-fanova "numpy<2"
ln -s /home/lgl/nas1/instances/uc_model_data data/instances   # 软链接, 只读

# LLM API 配置（.env 不提交到代码库）
cat > .env <<'EOF'
OPENAI_BASE_URL=<API 服务地址>
OPENAI_API_KEY=<密钥>
LLM_MODEL=<模型名>
# 服务器外网经本机 mihomo 代理（127.0.0.1:7890），openai SDK 自动读取以下变量
HTTP_PROXY=http://127.0.0.1:7890
HTTPS_PROXY=http://127.0.0.1:7890
NO_PROXY=127.0.0.1,localhost
EOF
```

依赖版本注意：SMAC 2.4.0 与 scikit-learn 1.9 不兼容（`sklearn.tree._tree.DTYPE`
已移除），需将 scikit-learn 固定在 `[1.6.1, 1.8)` 区间。

主要入口脚本（`scripts/`）：

| 脚本 | 功能 |
|---|---|
| `build_rag.py` | 构建手册检索库（一次性） |
| `observe_family.py` | 实例集特征提取（一次性，结果缓存） |
| `tune_campaign.py` | 执行一次完整调参任务（第 4 节流程） |
| `eval_test.py` | 最优配置的测试集评估 |
| `sequential_experiment.py` | 实例分批到达的顺序实验 |

注意事项：

- 评估 worker 各自缓存当前实例模型，8 个 worker 的内存占用在 503GB 总量下安全，
  但启动时应错峰，避免同时读取大文件；
- 手册检索库与 Gurobi 版本绑定（当前 13.0），求解器升级后需重建；
- 实例文件一律通过软链接访问，任何环节不得复制。
